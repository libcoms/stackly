# Telegram stackly: редакционная система

Канал: https://t.me/stacklyai · Бот: https://t.me/stackly_ai
Публикация: один пост ежедневно в 10:00 по Москве, автоматически.
Главная аудитория — преподаватели и репетиторы; дополнительные материалы — ученикам.

Тон: конкретный, спокойный, полезный. Один пост — одна мысль и одно действие.
Не выдумывать клиентов, отзывы, результаты, экономию времени и количество пользователей.
Не обещать автоматическую проверку развёрнутых решений и не приписывать ДЗ режим пробника:
режим пробника сейчас относится к сохранённым вариантам преподавателя.
Не публиковать данные учеников, реальные имена, почту и скриншоты личных кабинетов.
Примеры считать самостоятельно; текущие правила и номера ЕГЭ сверять с ФИПИ перед упоминанием.

## Ежедневный цикл

1. Прочитать план, последние опубликованные тексты и актуальные возможности проекта.
2. Подготовить полезный пост до 900 символов. Сохранить UTF-8 plain text в posts/YYYY-MM-DD.txt.
3. Создать отдельную квадратную обложку через imagegen. Следовать DESIGN.md: белая тетрадная
   бумага, тонкая сетка, синяя ручка, маленькое stackly. Крупный короткий заголовок; без ложных UI и цифр.
   Сохранить PNG/JPEG в images/YYYY-MM-DD.png. Записать промпт в posts/YYYY-MM-DD.prompt.md.
4. Проверить текст, изображение, ссылку https://stackly.su и факты. Проверить отсутствие доставки за сегодня.
5. Выполнить tools/telegram_publish.py publish --channel @stacklyai --date YYYY-MM-DD --post ... --image ... .
   Токен берётся из .env (STACKLY_TG_TOKEN или TOKEN); никогда не показывать и не передавать в аргументах.
6. marketing/.delivery/YYYY-MM-DD.json — квитанция доставки. При наличии sent не отправлять повторно.
   При sending/uncertain выяснить результат в канале вручную; не повторять автоматически.
   Не публиковать два поста в один день и не навёрстывать пропущенные дни пачкой.

Автоматизация Codex работает при доступном локальном исполнителе. Не считать подготовленный
черновик опубликованным; успешная публикация подтверждается message_id из Telegram.
