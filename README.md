# stackly

Платформа для репетиторов и преподавателей любого предмета: группы, домашние задания с автопроверкой
и статистика по ученикам. Внутри готовый курс ЕГЭ по информатике: все 27 заданий, учебник Python и банк задач.
Сайт работает на https://stackly.su.

## Состав

| `deploy/` | установка на сервер: nginx, systemd-сервисы, ночные резервные копии, `install.sh`, `update.sh` |
| `tests/` | тесты API и независимая проверка ответов задач №1–5, №7, №8, №9, №11 и №19–21 банка |

| `tools/gen_task2.py` | генератор задач №2 (фрагмент таблицы истинности): формула, строки и пропуски подбираются так, чтобы ответ был единственным |

| `tools/gen_task4.py` | генератор задач №4 (условие Фано): кратчайшее слово для буквы (в том числе с запасом для других букв), наименьшая сумма длин, сколько букв ещё поместится, длина слова по Хаффману, троичный код, длина сообщения при части известных кодов; ответ — перебор длин с жадной раскладкой по свободным веткам, тест проверяет обходом дерева; описание в `<!--spec:…-->` |
| `tools/gen_task5.py` | генератор задач №5 (алгоритм строит R по N): правило, вопрос, пример и решение из одного описания; описание хранится в задаче комментарием `<!--spec:…-->` для проверки |
| `tools/gen_task7.py` | генератор задач №7 (изображения, звук, видео, передача по каналу): объём, наибольшая палитра, перекодировка, повторная оцифровка, сжатие; числа подбираются так, чтобы ответ был целым там, где условие не просит округлять; в пояснении — решение вручную; описание в `<!--spec:…-->` |
| `tools/gen_task8.py` | генератор задач №8 (комбинаторика): слова, перестановки, числа в системах счисления и номер в алфавитном списке; условие, решение и ответ строятся из одного описания (`<!--spec:…-->`), для простых задач к пояснению добавляется решение по формуле |
| `tools/gen_task9.py` | генератор задач №9 (строки таблицы): условия из набора проверок, файл данных на 300 строк для каждой задачи |
| `tools/gen_task11.py` | генератор задач №11 (пароли, идентификаторы, номера): объём для K записей, доп. сведения, наибольший алфавит, длина и число записей, запись из нескольких полей, номер из двух частей, наименьшая длина для M кодов; описание в `<!--spec:…-->` |
| `tools/gen_task19.py` | генератор задач №19–21 (игры с кучами камней): одна игра — комплект из трёх задач: условие игры в задании 19, задания 20 и 21 ссылаются на него. В банке у таких задач есть строка «Комплект 19–21» и ссылка `#set-<id>`, открывающая все три задачи подряд |
| `.github/workflows/` | CI (тесты, проверка nginx) и автодеплой из `main` |

База — SQLite, файл `/var/lib/stackly/stackly.db` на сервере (в репозиторий не попадает).
Резервные копии — каждую ночь в `/var/backups/stackly`, хранятся 14 дней.

## Доступ к материалам

Методичка (`#ege`), шпаргалка (`#cheat`), банк задач (`#bank`), ДЗ и кабинет открываются только после входа.
Гостю доступны главная, учебник Python и страница входа.

- Материалы лежат в `content/ege.js`, а не в `public/`. На сервере это `/opt/stackly/content`, вне папки сайта,
  поэтому nginx их не раздаёт. Файл отдаёт API (`GET /api/content/ege.js`) только по действующей сессии,
  гость получает 401.
- `index.html` хранит лишь карточки 27 заданий (название, уровень, время) для карты экзамена на главной.
  Правите название, уровень, время или описание задания в `content/ege.js` — поправьте и карточку в `index.html`.
  Расхождение поймает тест `tests/test_content.py`.
- Правки из редактора (`GET /api/content`) гость получает урезанными: без задач и без текстов разборов,
  только правки учебника Python и полей карточек заданий.
- Картинки из редактора (`/api/media/<id>`) открыты по прямой ссылке: адрес случайный, но кто его знает — увидит.
- После входа страница перезагружается и подтягивает материалы, после выхода — перезагружается и забывает их.

## Локально

```bash
python3 tools/dev_server.py                 # сайт + API на http://127.0.0.1:8000
python3 -m unittest discover -s tests -v    # тесты API
```

## Сервер

Первая установка (Ubuntu):

```bash
sudo bash deploy/install.sh ваш-домен.ru
```

Сертификат Reg.ru: положите `fullchain.crt` (сертификат + цепочка CA) и `private.key` в `/etc/ssl/stackly/`
**до** запуска `install.sh`. Без них будет выпущен бесплатный сертификат Let's Encrypt.

Почта для восстановления пароля: заполните `SMTP_*` в `/etc/stackly/stackly.env`, затем
`systemctl restart stackly-api`.

Если письмо не доходит, пароль задаётся на сервере: `sudo bash deploy/set-password.sh почта@пример.ру`.
Пароль спрашивается дважды и на экране не виден; после смены все сессии пользователя закрываются.
Локально: `python3 app/stackly_api.py set-password почта@пример.ру` (база — `STACKLY_DB`).

Обновление вручную: `sudo bash deploy/update.sh` из папки с новой версией. Скрипт делает копию базы,
обновляет сайт, API, сервисы и конфиг nginx (домен и сертификат берутся из текущей установки).

## Дизайн и навигация

Визуальная система «Тетрадь» описана в `DESIGN.md`, продуктовый контекст — в `PRODUCT.md`. Коротко: лист в клетку,
номера и сроки — на полях слева за красной линией, синий — действия, красный — сроки и ошибки, зелёный — сделано.
У каждой роли своя боковая панель (на телефоне — нижняя панель): ученик — Главная, Задания, Материалы, Банк задач, Прогресс
и счётчик баллов; учитель — Группы, Материалы, Банк задач, Редактор задач, Награды и эфир, Тариф; администратор — ещё Обзор, Пользователи, Все группы,
Общий банк, Посещаемость. Пункты собирает `navItems()` в `public/index.html`. Вверху рабочих страниц — строка «Дальше»
с ближайшим шагом.

## Баллы и магазин

Ученик получает баллы за учёбу: верно решённая задача — 10 (ещё 5, если с первой попытки), изученная тема Python,
разобранное задание или материал — 5, пройденный уровень фермы — 10, день с занятиями — 5. Баллы считаются из прогресса по одной формуле на сайте
(`pointsOf()`) и на сервере (`points()` в `app/stackly_api.py`). Главная ученика (`#start`) показывает баллы и уровень,
ближайшее задание, модуль, который стоит пройти, и рекомендации.

## Ферма (`#farm`)

Игра в духе The Farmer Was Replaced для тех, кто впервые видит Python: ученик пишет программу, дрон выполняет её на
грядках. Каждый уровень объясняет одну новую вещь простыми словами и с примером. 22 уровня в восьми главах (`CHAPTERS`
в `farm.js`); номер уровня для ученика — его место в этом порядке, а в адресе (`#farm-<id>`) и прогрессе — постоянный id:

| Глава | Что узнаёт ученик |
|---|---|
| 1. Первые команды | команда и скобки, команда с аргументом, программа из многих строк, `print`, текст и числа |
| 2. Переменные | переменная — «коробка с именем», переменная-счётчик меняется |
| 3. Циклы | `for` и `range`, что считает `range`, `while True`, `while` с условием |
| 4. Условия | `if`, `if / else`, сравнения `< > == !=` |
| 5. Всё поле | цикл в цикле, аргументы, вспашка, остаток `%` |
| 6. Свои функции | `def`, `return`, `elif` |
| 7. Списки | список, `append`, `sort` |
| 8. Своя ферма | дерево улучшений (открывается после уровня «Кусты») |

Цели уровня: собрать урожай (`goal`) — засчитывается сразу; или проверяется, когда программа закончилась: что
выведено в журнал (`out`), как выглядит поле (`pattern`), «ровно столько» (`exact`), есть ли в коде нужная конструкция
(`codeHas` — например, без `for` уровень про цикл не засчитать). Если не вышло, журнал объясняет по пунктам: «В журнале
должно быть: «1» … «5». А программа вывела: «0» … «4»». После двух неудачных запусков появляется «Показать решение»
с кнопкой «Вставить в редактор».

Уровень открывается после предыдущего, преподавателю и администратору открыты все. Пункт «Ферма» есть в боковой
панели, ученику — ещё карточка в «Материалах». У уровня — ссылки на темы учебника Python, обратно — блок «В игре «Ферма»»
у темы учебника (`#py-N`). Карта для ссылок — `FARM_LV` в `index.html`, копия `LEVELS` из `farm.js` (расхождение ловит
`tests/farm_check.js`).

Экран — как в игре: парящий низкополигональный островок в 3D с дроном, поверх — перетаскиваемые окна «Задание» и
`уровень_N.py` (кнопки ▶ ▷ ■ ⏸ ↺, вывод программы внизу окна), ресурсы с иконками слева вверху, кнопки «Уровни» и
«Команды» справа, скорость слева внизу. Положение и размер окон помнятся в браузере. На ширине меньше 860 px окна
встают под сценой. `#farm` открывает первый непройденный уровень со списком уровней.
3D рисует Three.js r160 (MIT) из `public/vendor/three-0.160.0.module.min.js` — файл лежит на сайте, потому что CSP
не пускает скрипты с других доменов, и грузится только на странице фермы. Без WebGL поле рисуется плоской сеткой.

- Всё в `public/farm.js`: свой интерпретатор подмножества Python (CSP сайта запрещает eval, поэтому Pyodide и Skulpt не подходят),
  поле, уровни и экран. Поддержаны целые любой длины (BigInt, когда число не помещается), float с делением как в Python,
  побитовые операции, строки (`replace` с числом замен, `split`, `strip`, `isalpha`…), списки, кортежи, словари, множества,
  f-строки с форматами (`{x:08b}`, `{x:.2f}`), `if/elif/else`, `while`, `for`, `break/continue`, `def` со значениями по умолчанию,
  `lambda`, `global`, декораторы, генераторы списков, множеств и словарей, `*args` в вызове, `with open(…) as f`, `import` модулей
  `math`, `itertools` (`product`, `permutations`, `combinations`), `functools` (`lru_cache`, `cache`, `reduce`), `sys`, `fnmatch`.
  `all()`/`any()` с генератором останавливаются на первом ответе. Вызовы функций идут через свой стек кадров («батут» `drive()`),
  поэтому рекурсия ограничена, как в Python, 1000 вызовами и поднимается `sys.setrecursionlimit` (до 20 000).
  Ошибки — с типом как в Python, номером строки и объяснением по-русски.
- Каждая команда дрону — один ход; у уровня лимит ходов и норма для звезды (ход эталонного решения).
- Прогресс — `farm: {"номер": лучшее число ходов}` в общем прогрессе; первое прохождение уровня даёт 10 баллов
  (событие `k: 'f'`, учитывается и в «баллах за неделю»). Код каждого уровня хранится в браузере.
- Проверка: `node tests/farm_check.js` (запускается и из `tests/test_farm.py`): интерпретатор считает как Python,
  эталонное решение каждого уровня проходит его (и укладывается в норму, если она есть), стартовый код — нет, типичные ошибки новичка объясняются, а решения без нужного
  приёма (шахматный порядок, сортировка, уборка сгнивших тыкв) не укладываются в лимит. Меняете уровень или правила
  поля — пересчитайте нормы `PAR` в `farm.js`. Там же проверяются подсказки редактора и дерево улучшений.
- **Подсказки в редакторе** (`complete()`, `signature()`, `insertion()` в `farm.js`). При наборе — список: команды дрона,
  открытые на этом уровне, направления, `Entities.`/`Items.`/`Grounds.` (в своей ферме — только купленные растения),
  свои функции и переменные из программы, встроенные функции и слова Python, после точки — методы списков, строк и словарей.
  У выбранного — описание. ↑ ↓ — выбрать, Tab/Enter — вставить (у функции сразу скобки, курсор внутри, если нужны аргументы),
  Esc — закрыть. Внутри скобок вызова показывается справка по аргументам. В строках и комментариях подсказок нет.
- **Своя ферма** (`#farm-12`, открывается после уровня «Кусты») — режим как в оригинальной игре: урожай копится в амбаре между
  запусками, за него покупаются улучшения (кнопка «+»): «Посадка», «Расширение поля» (3×3 → 8×8), «Учёт», «Координаты»,
  «Деревья», «Вспашка», «Удобрение» (рост на 20% быстрее за ступень), «Сенсор», «Щедрый урожай» (×2), «Тыквы»,
  «Подсолнухи». Цены и зависимости — `UPGRADES` в `farm.js`. Скорость «Макс» здесь выключена: время идёт по-настоящему.
  Амбар и улучшения — `farmx: {t, items, up}` в общем прогрессе: во время работы программы пишутся в браузер раз в 3 с,
  в аккаунт — после остановки и покупки; при входе берётся более свежая копия. Баллов за свою ферму нет.

Потратить баллы можно в магазине (`#shop`): оформление профиля (цвет шара, рамка, значок у имени — видит и учитель),
заморозка серии (закрывает пропущенный день, до 2 в запасе), награды, которые учитель задаёт сам, и сообщения в эфир.
Траты хранятся в таблице `spends`; баланс = заработано − потрачено, отклонённое учителем возвращается.

Эфир (`#teach-shop`): учитель включает приём сообщений, задаёт цену и ссылку на трансляцию (например, Kinescope).
Оверлей `/live.html#<секрет>` показывает одобренные сообщения поверх видео и читает их голосом (Web Speech API).
В OBS его добавляют источником «Браузер»; при вебинаре из браузера — открывают во вкладке и нажимают «Включить звук».
Сообщения озвучиваются сразу; ещё не прозвучавшее учитель может снять — баллы вернутся.
Голоса — из браузера (Web Speech API), логика выбора общая для сайта и оверлея: `public/voice.js`. Учитель задаёт голос по
умолчанию и скорость, ученик — стиль для своего сообщения: женский, мужской или с армянским акцентом (русский текст
переписывается армянскими буквами и читается армянским голосом). Самые естественные голоса — в Microsoft Edge.

Опрос в эфире (там же, `#teach-shop`): учитель задаёт вопрос и 2–6 вариантов, баллы за ответ (до 100) и таймер.
Ученики его групп видят карточку опроса на любой странице сайта (сайт спрашивает `/api/polls` раз в 4 секунды, пока
вкладка открыта), оверлей показывает вопрос и живые результаты. Без верного ответа баллы начисляются сразу за любой
ответ; если учитель отметил верный, это викторина: баллы получают ответившие верно, когда опрос закроется (кнопкой или по
таймеру), а до этого ученики не видят ни верного ответа, ни результатов. Одновременно идёт один опрос; новый закрывает
прежний. Таблицы `polls` и `poll_votes`, начисления — строки `spends` с `kind = 'poll'` и отрицательной ценой.

## Мотивация: бонусы, достижения, цель группы

Начисляет сервер при сохранении прогресса (`PUT /api/progress` возвращает `rewards`, сайт поздравляет карточкой):

- **Задание в срок** — +20 баллов, если сдано за сутки до срока и раньше — +30 (`HW_BONUS`, `HW_EARLY_BONUS`).
  Просроченное — без бонуса. Подсказка о бонусе — на карточках заданий.
- **Достижения** — 14 вех (задачи, задачи с первой попытки, серия, задания в срок, темы, опросы эфира) с разовой
  наградой 10–200 баллов (`ACHIEVEMENTS`). На главной ученика — три ближайших с прогрессом и список всех.
- **Цель группы на неделю** — вместе решить 10 задач на ученика с понедельника (`GOAL_PER_STUDENT`). Когда цель
  достигнута, каждый, кто решал задачи на этой неделе, получает +30 (`GOAL_BONUS`). Видна на главной, в рейтинге и учителю.

Каждое начисление — строка `spends` с отрицательной ценой (`kind` = `hw`, `ach`, `goal`), повтор исключает уникальный
индекс `spends_once`. В «баллы за 7 дней» рейтинга достижения не входят: при запуске ученики с историей получили их разом.

## Рейтинг группы

Ученик видит рейтинг своей группы в разделе «Рейтинг» (`#rating`), учитель — на странице группы. Показатели: баллы за
последние 7 дней (задачи по времени верного ответа, темы и разборы по журналу событий, дни занятий, опросы эфира), все
заработанные баллы (потраченные в магазине тоже считаются), серия, решённые задачи и точность — в ней только ученики
от 10 попыток (`RATING_DAYS`, `RATING_MIN_TRIES` в `app/stackly_api.py`). Одинаковый показатель — одно место. Ученикам
видны только имена и оформление одногруппников, без почты. Учитель может скрыть рейтинг от учеников в настройках группы.

## Учителя и домашние задания

Роли: **ученик**, **учитель** (преподаватель), **администратор**. При регистрации человек сам выбирает,
преподаватель он или ученик; администратора назначают на сервере.

- Учитель создаёт группы в разделе «Группы» (`#teach`). У каждой группы свой код: ученик вводит его
  в разделе «Задания» (или в «Прогрессе») и попадает в группу.
- У каждой задачи банка свой сквозной номер (#1, #2, …). В банке и в редакторе ДЗ задачи ищутся
  по номеру или диапазону («17», «5-9», «3, 12, 30-33»), по номеру задания ЕГЭ, сложности и тексту условия.
- Домашнее задание выдаётся группе или выбранным ученикам: задачи банка, темы Python, разборы
  заданий методички, срок сдачи и комментарий.
- Задачи 19–21 одной игры — комплект: отметили одну, и в задание сами добавятся все три (по порядку 19, 20, 21);
  убрали одну — уходит весь комплект.
- Ученик видит задания в разделе «Задания» (`#hw`): сверху самое срочное, ниже остальные несданные и «Выполненные». Каждое задание открывается
  одной страницей (`#hw-<id>`): разборы, темы и задачи с проверкой ответа — без переходов между страницами.
- Учитель по каждому заданию видит статистику (`#teach-hwv-<id>`): кто сдал и когда, таблица
  «ученик × пункт» с числом попыток, сводка по каждой задаче.
- В группе — таблица учеников (решено, точность, серия, активность, сданные ДЗ) и карточка каждого ученика.
- **Материалы** (`#materials`). Преподаватель отмечает предметы, которые ведёт, и включает готовые модули
  (сейчас они есть по информатике: разборы ЕГЭ, учебник Python, шпаргалка, обзор экзамена). Ученики видят
  в «Материалах» и в своём кабинете только модули, включённые их учителями. Вкладки Python и разборов
  в подборе ДЗ тоже появляются, только если модули включены.
- **Тарифы преподавателей.** Бесплатный — до 5 групп, до 5 учеников во всех группах и до 2 ГБ (картинки, свои задачи
  с файлами, материалы, ДЗ). Про — без ограничений, плюс материалы платформы (разборы ЕГЭ, учебник Python, шпаргалка):
  ученик видит их, только пока у его преподавателя действует Про. Новому преподавателю — пробный Про на 14 дней,
  один раз (`TRIAL_DAYS`, `FREE_LIMITS` в `app/stackly_api.py`). Лимиты проверяет сервер: создание группы, вступление
  ученика по коду, сохранение картинок, задач и материалов; уже созданное после окончания Про остаётся.
  Оплаты на сайте нет: тариф и срок ставит администратор в карточке преподавателя. Поля `users.plan` (free/trial/pro)
  и `users.plan_until` (у Про без даты — бессрочно). Учителя, которые были до тарифов, получили пробный Про с дня обновления.
- **Telegram-бот** (`app/stackly_bot.py`, сервис `stackly-bot`). Для преподавателя — на тарифе Про: уведомления
  «ученик выполнил задание» и «новый ученик в группе», сводка, когда прошёл срок ДЗ (кто сдал, кто нет), вечерняя
  сводка в 20:00 по Москве; команды `/hw`, `/groups`, `/student Имя`, `/settings`, `/stop`; кнопка «Напомнить
  не сдавшим» (не чаще раза в 6 часов на задание). Ученик подключает бота, чтобы получать эти напоминания,
  и по `/hw` видит, что осталось сделать. Подключение — в кабинете (блок «Telegram»): одноразовая ссылка
  `t.me/<бот>?start=<токен>` на 15 минут. API в Telegram не ходит — кладёт сообщения в очередь `tg_outbox`,
  отправляет их бот. Настройка на сервере: создайте бота у @BotFather, впишите `STACKLY_TG_TOKEN` и `STACKLY_TG_BOT`
  (имя без @) в `/etc/stackly/stackly.env`, затем `systemctl restart stackly-api stackly-bot`. Без токена бот
  не запускается, а блок в кабинете видит только администратор (с подсказкой). Тест — `tests/test_bot.py`
  (поддельный Bot API на локальном порту).
- **Оплата Про через ЮKassa.** Преподаватель выбирает 1 месяц (350 ₽) или 12 месяцев (3 700 ₽) на странице «Тариф Про» (`#teach-pro`)
  (`POST /api/pay/pro`), платит на странице ЮKassa и возвращается на `#pay-return`, где сайт сверяет платёж
  (`POST /api/pay/check`). Уведомление ЮKassa приходит на `POST /api/pay/webhook`. В обоих случаях сервер не верит
  присланному, а запрашивает платёж у ЮKassa и проверяет статус, сумму, валюту и пользователя. Оплаченный срок
  прибавляется к действующему Про или пробному периоду, один платёж засчитывается один раз (таблица `payments`).
  Автопродления нет; возвраты — вручную в кабинете ЮKassa, тариф после возврата администратор меняет в карточке.
  Настройка: `STACKLY_YK_SHOP` и `STACKLY_YK_KEY` в `/etc/stackly/stackly.env`, адрес уведомлений в кабинете ЮKassa.
  Цены — `PRO_PRICES` в `app/stackly_api.py` и `PRO_PRICE` в `public/index.html` (оферта и главная). Тест — `tests/test_pay.py`.
- **Документы.** Публичная оферта — `#offer`, политика обработки персональных данных — `#privacy`, тарифы
  и порядок оплаты и получения доступа — `#pricing`. Всё открывается без входа (этого требует ЮKassa при
  подключении платежей), ссылки — в подвале, тарифы — ещё и в шапке гостя. Контакты и реквизиты исполнителя
  показываются только в оферте (раздел 13) и, как у оператора данных, в политике; старая ссылка `#contacts` ведёт
  на оферту. Реквизиты — `EXECUTOR` в `public/index.html`.
- **Карточка пользователя** (`#admin-u-<id>`, `GET /api/admin/user`). Администратор открывает её из «Пользователей»
  или «Обзора»: у преподавателя — тариф с формой смены (`POST /api/admin/plan`), занятые лимиты, группы, материалы;
  у ученика — прогресс, группы с преподавателями, выполненные ДЗ и ссылка на подробную статистику.
  В «Материалах» администратор видит материалы всех преподавателей, сгруппированные по авторам.
- **Интерактивные модули** (тариф Про) — блоки разметки в материалах и задачах, кнопки «график» и «карточки»
  в панели редактора. ```` ```график ```` — функция с ползунками: строки `y = a*x^2 + b*x + c` (до трёх функций),
  параметры `a = 1 (-3..3)` (до четырёх, буквы кроме e, x, y), области `x = -6..6` и `y = -4..10`. Формулу разбирает
  свой парсер без eval (числа, + − * / ^, скобки, sin cos tan sqrt abs ln log exp, pi, e; «2x» = 2*x).
  ```` ```карточки ```` — по строке на карточку, стороны через `|`, карточка переворачивается по нажатию.
  На бесплатном тарифе сервер не сохраняет материал или задачу с такими блоками (`check_ix`).
- **Подробный разбор задания** — необязательное поле `guide` у задания в `content/ege.js` (сейчас есть у задания 8): части
  с текстом и рисунками, блоками «Руками» и «Кодом», карточками и модулями комбинаторики — дерево вариантов, правило
  произведения, словарь «номер ↔ слово» и лаборатория перебора, которая сама пишет программу на Python (`KX` в `public/index.html`).
  Примеры кода из разбора запускает тест `tests/test_bank_task8.py`.
- **Свои материалы** (`#mat-new`, `#mat-<id>`, `#mat-edit-<id>`). Учитель собирает материал — текст в разметке сайта
  с формулами, таблицами, картинками и рисунками. Ученик видит материал, если учитель отметил «Показывать ученикам
  моих групп» или выдал его в ДЗ (вкладка «Материалы» в подборе). В ДЗ материал показывается целиком, пункт
  закрывается кнопкой «Отметить изученным». Удалённый материал скрывается, но не стирается. API: `GET/POST /api/materials`,
  `POST /api/materials/delete`; таблица `materials`, в ДЗ — `items.mat`, в прогрессе ученика — `mats`.
- **Рисунок.** В панели разметки любого редактора (задачи, методичка, материалы) есть кнопка «рисунок»: холст с карандашом,
  линией, стрелкой, прямоугольником, эллипсом, текстом и ластиком, шестью цветами, тремя толщинами, отменой и листом
  в клетку. Рисунок сохраняется картинкой PNG (`POST /api/media`) и встаёт в текст как `![](media:ID)`.
  Нажатие на картинку в превью открывает её на холсте — можно дорисовать, ссылка в тексте заменится на новую.
- Администратор видит обзор платформы (`#admin-home`): учителя с группами, учениками, заданиями, задачами
  и занятой памятью (картинки, свои задачи с файлами данных и выданные ДЗ), сводку по ученикам.
  Роли назначаются в «Пользователях» (`#admin`).

### Редактор (`#edit`)

- **Задачи.** Учитель создаёт свои задачи и правит только их. Задача относится либо к заданию ЕГЭ по информатике
  (1–27), либо к любому предмету: тогда указывают предмет и тему, а в банке и подборе ДЗ задачи фильтруются по предмету.
  Новые задачи получают постоянные номера с #1001.
- **Кто видит задачу.** Преподаватели и администратор видят общий банк платформы (встроенные задачи и задачи
  администратора). Свою задачу преподаватель по умолчанию видит один; её можно открыть всем преподавателям.
  **Ученик видит только задачи, выданные ему в ДЗ** — проверяет сервер: `GET /api/content/ege.js` отдаёт ученику
  банк только из этих задач (у каждой поле `n` — сквозной номер из полного банка), `GET /api/content` — только их правки.
  Выданная задача остаётся видна ученику, даже если автор потом её закроет.
- **Банк задач** (`#bank`) устроен по шагам: сетка номеров ЕГЭ и список предметов → список задач номера (`#bank-5`)
  или предмета (`#bank-s-<предмет>`) с фильтрами сложности и статуса → страница задачи (`#p-<id>`) с переходом
  к соседним. Комплект 19–21 — `#set-<id>`.
  Выдать в ДЗ чужую закрытую задачу нельзя: сервер это проверяет. Чужую или встроенную задачу можно скопировать
  и править копию. Администратор правит любые задачи, включая встроенные (#1–#562): правка хранится
  поверх встроенной, исходник можно вернуть, задачу можно скрыть из банка.
- **Методичка** (только администратор): разборы 27 заданий и 43 темы Python. Правки хранятся поверх
  встроенного текста, есть сброс к исходному.
- **Разметка** условий и текстов: `**жирный**`, `*курсив*`, `` `код` ``, `2^10^`, `log~2~`, списки
  (`- `, `1. `), таблицы (`| a | b |`), блоки `` ``` ``, картинки (загружаются кнопкой, хранятся в базе).
  Служебный символ как обычный — через `\`: `\^`, `\*`. Разметка всегда превращается в безопасный HTML.
- Картинки — PNG, JPEG, WebP, GIF до 1,5 МБ (большие уменьшаются в браузере перед загрузкой), SVG не принимаются.

### Посещаемость (`#admin-stats`)

Администратор видит посещаемость в разделе «Посещаемость» (пункт боковой панели и меню аккаунта):
сколько человек на сайте сейчас, посетители, визиты и просмотры за сегодня и за 7, 30, 90 дней или год,
график по дням (за год — по неделям), популярные страницы, источники переходов, телефоны и компьютеры, регистрации.

- Сайт при каждом переходе отправляет `POST /api/hit` с названием раздела (`bank-19`, `ege-5`, `hw`…) — без id задач,
  групп и ДЗ. Источник (`yandex.ru`, `vk.com`) отправляется только при открытии сайта.
- IP-адреса не хранятся и cookie для подсчёта не ставятся. Посетитель — хеш IP и браузера с солью дня,
  соль удаляется через два дня, поэтому одного человека можно узнать только в пределах суток.
- Боты и запросы без браузера не считаются. Записи старше 400 дней удаляются. Дни считаются по московскому времени.

Первого администратора назначают на сервере (пользователь должен быть зарегистрирован на сайте):

```bash
sudo bash deploy/set-role.sh почта@пример.ру admin
```

Прогресс и проверка ответов работают в браузере ученика, сервер хранит то, что прислал браузер.
Для домашних заданий этого достаточно, но технически подкованный ученик может отметить задачу
решённой, не решая её.

## Автодеплой

Каждое изменение в ветке `main` проходит тесты и само выкладывается на сервер
(`.github/workflows/deploy.yml`). Для этого в Settings → Secrets and variables → Actions нужны секреты:

| Секрет | Значение |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | пользователь SSH (`root` или пользователь с sudo без пароля) |
| `DEPLOY_SSH_KEY` | приватный ключ, открытый ключ которого добавлен в `~/.ssh/authorized_keys` на сервере |
| `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan -H <адрес сервера>` |

Пока секретов нет, деплой пропускается. Запустить вручную: Actions → Deploy → Run workflow.
