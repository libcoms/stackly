# stackly

Методичка по ЕГЭ по информатике: все 27 заданий, учебник Python и банк задач с проверкой ответов.
Сайт работает на https://stackly.su.

## Состав

| Папка | Что внутри |
|---|---|
| `public/` | сайт: одна страница `index.html` (HTML, CSS и JS в одном файле) и `favicon.svg` |
| `content/` | закрытые материалы `ege.js`: методичка по 27 заданиям, шпаргалка и банк задач. Отдаются только вошедшим |
| `app/stackly_api.py` | API: регистрация, вход, сброс пароля, прогресс. Только стандартный Python 3.10+, без пакетов |
| `deploy/` | установка на сервер: nginx, systemd-сервисы, ночные резервные копии, `install.sh`, `update.sh` |
| `tests/` | тесты API |
| `tools/dev_server.py` | локальный просмотр сайта вместе с API |
| `.github/workflows/` | CI (тесты, проверка nginx) и автодеплой из `main` |

База — SQLite, файл `/var/lib/stackly/stackly.db` на сервере (в репозиторий не попадает).
Резервные копии — каждую ночь в `/var/backups/stackly`, хранятся 14 дней.

## Доступ к материалам

Методичка (`#ege`), шпаргалка (`#cheat`), банк задач (`#bank`), ДЗ и кабинет открываются только после входа.
Гостю доступны главная, учебник Python и страница входа.

- Материалы лежат в `content/ege.js`, а не в `public/`. На сервере это `/opt/stackly/content`, вне папки сайта,
  поэтому nginx их не раздаёт. Файл отдаёт API (`GET /api/content/ege.js`) только по действующей сессии,
  гость получает 401.
- `index.html` хранит лишь карточки 27 заданий (название, уровень, время) для карты экзамена на главной.
  Правите название, уровень, время или описание задания в `content/ege.js` — поправьте и карточку в `index.html`.
  Расхождение поймает тест `tests/test_content.py`.
- Правки из редактора (`GET /api/content`) гость получает урезанными: без задач и без текстов разборов,
  только правки учебника Python и полей карточек заданий.
- Картинки из редактора (`/api/media/<id>`) открыты по прямой ссылке: адрес случайный, но кто его знает — увидит.
- После входа страница перезагружается и подтягивает материалы, после выхода — перезагружается и забывает их.

## Локально

```bash
python3 tools/dev_server.py                 # сайт + API на http://127.0.0.1:8000
python3 -m unittest discover -s tests -v    # тесты API
```

## Сервер

Первая установка (Ubuntu):

```bash
sudo bash deploy/install.sh ваш-домен.ru
```

Сертификат Reg.ru: положите `fullchain.crt` (сертификат + цепочка CA) и `private.key` в `/etc/ssl/stackly/`
**до** запуска `install.sh`. Без них будет выпущен бесплатный сертификат Let's Encrypt.

Почта для восстановления пароля: заполните `SMTP_*` в `/etc/stackly/stackly.env`, затем
`systemctl restart stackly-api`.

Обновление вручную: `sudo bash deploy/update.sh` из папки с новой версией. Скрипт делает копию базы,
обновляет сайт, API, сервисы и конфиг nginx (домен и сертификат берутся из текущей установки).

## Учителя и домашние задания

Роли: **ученик** (по умолчанию), **учитель**, **администратор**.

- Учитель создаёт группы в разделе «Учителю» (`#teach`). У каждой группы свой код: ученик вводит его
  в личном кабинете и попадает в группу.
- У каждой задачи банка свой сквозной номер (#1, #2, …). В банке и в редакторе ДЗ задачи ищутся
  по номеру или диапазону («17», «5-9», «3, 12, 30-33»), по номеру задания ЕГЭ, сложности и тексту условия.
- Домашнее задание выдаётся группе или выбранным ученикам: задачи банка, темы Python, разборы
  заданий методички, срок сдачи и комментарий.
- Ученик видит задания в разделе «ДЗ» (`#hw`): «Предстоит» и «Выполненные». Каждое задание открывается
  одной страницей (`#hw-<id>`): разборы, темы и задачи с проверкой ответа — без переходов между страницами.
- Учитель по каждому заданию видит статистику (`#teach-hwv-<id>`): кто сдал и когда, таблица
  «ученик × пункт» с числом попыток, сводка по каждой задаче.
- В группе — таблица учеников (решено, точность, серия, активность, сданные ДЗ) и карточка каждого ученика.
- Администратор назначает роли (`#admin`) и видит все группы.

### Редактор (`#edit`)

- **Задачи.** Учитель создаёт свои задачи и правит только их. Новые задачи получают постоянные номера
  с #101 и сразу попадают в общий банк и в подбор для ДЗ. Чужую или встроенную задачу можно скопировать
  и править копию. Администратор правит любые задачи, включая встроенные (#1–#62): правка хранится
  поверх встроенной, исходник можно вернуть, задачу можно скрыть из банка.
- **Методичка** (только администратор): разборы 27 заданий и 43 темы Python. Правки хранятся поверх
  встроенного текста, есть сброс к исходному.
- **Разметка** условий и текстов: `**жирный**`, `*курсив*`, `` `код` ``, `2^10^`, `log~2~`, списки
  (`- `, `1. `), таблицы (`| a | b |`), блоки `` ``` ``, картинки (загружаются кнопкой, хранятся в базе).
  Служебный символ как обычный — через `\`: `\^`, `\*`. Разметка всегда превращается в безопасный HTML.
- Картинки — PNG, JPEG, WebP, GIF до 1,5 МБ (большие уменьшаются в браузере перед загрузкой), SVG не принимаются.

Первого администратора назначают на сервере (пользователь должен быть зарегистрирован на сайте):

```bash
sudo bash deploy/set-role.sh почта@пример.ру admin
```

Прогресс и проверка ответов работают в браузере ученика, сервер хранит то, что прислал браузер.
Для домашних заданий этого достаточно, но технически подкованный ученик может отметить задачу
решённой, не решая её.

## Автодеплой

Каждое изменение в ветке `main` проходит тесты и само выкладывается на сервер
(`.github/workflows/deploy.yml`). Для этого в Settings → Secrets and variables → Actions нужны секреты:

| Секрет | Значение |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | пользователь SSH (`root` или пользователь с sudo без пароля) |
| `DEPLOY_SSH_KEY` | приватный ключ, открытый ключ которого добавлен в `~/.ssh/authorized_keys` на сервере |
| `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan -H <адрес сервера>` |

Пока секретов нет, деплой пропускается. Запустить вручную: Actions → Deploy → Run workflow.
