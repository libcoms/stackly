# stackly

Платформа для репетиторов и преподавателей любого предмета: группы, домашние задания с автопроверкой
и статистика по ученикам. Внутри готовый курс ЕГЭ по информатике: все 27 заданий, учебник Python и банк задач.
Сайт работает на https://stackly.su.

## Состав

| Папка | Что внутри |
|---|---|
| `public/` | сайт: одна страница `index.html` (HTML, CSS и JS в одном файле) и `favicon.svg` |
| `content/` | закрытые материалы `ege.js`: методичка по 27 заданиям, шпаргалка и банк задач. Отдаются только вошедшим |
| `app/stackly_api.py` | API: регистрация, вход, сброс пароля, прогресс. Только стандартный Python 3.10+, без пакетов |
| `deploy/` | установка на сервер: nginx, systemd-сервисы, ночные резервные копии, `install.sh`, `update.sh` |
| `tests/` | тесты API и независимая проверка ответов задач №1, №2, №5, №9 и №19–21 банка |
| `tools/dev_server.py` | локальный просмотр сайта вместе с API |
| `tools/gen_task1.py` | генератор задач №1 (граф + таблица): строит схемы, проверяет однозначность ответа, выдаёт JSON для банка |
| `tools/gen_task2.py` | генератор задач №2 (фрагмент таблицы истинности): формула, строки и пропуски подбираются так, чтобы ответ был единственным |
| `tools/gen_task5.py` | генератор задач №5 (алгоритм строит R по N): правило, вопрос, пример и решение из одного описания; описание хранится в задаче комментарием `<!--spec:…-->` для проверки |
| `tools/gen_task9.py` | генератор задач №9 (строки таблицы): условия из набора проверок, файл данных на 300 строк для каждой задачи |
| `tools/gen_task19.py` | генератор задач №19–21 (игры с кучами камней): одна игра — комплект из трёх задач: условие игры в задании 19, задания 20 и 21 ссылаются на него. В банке у таких задач есть строка «Комплект 19–21» и ссылка `#set-<id>`, открывающая все три задачи подряд |
| `.github/workflows/` | CI (тесты, проверка nginx) и автодеплой из `main` |

База — SQLite, файл `/var/lib/stackly/stackly.db` на сервере (в репозиторий не попадает).
Резервные копии — каждую ночь в `/var/backups/stackly`, хранятся 14 дней.

## Доступ к материалам

Методичка (`#ege`), шпаргалка (`#cheat`), банк задач (`#bank`), ДЗ и кабинет открываются только после входа.
Гостю доступны главная, учебник Python и страница входа.

- Материалы лежат в `content/ege.js`, а не в `public/`. На сервере это `/opt/stackly/content`, вне папки сайта,
  поэтому nginx их не раздаёт. Файл отдаёт API (`GET /api/content/ege.js`) только по действующей сессии,
  гость получает 401.
- `index.html` хранит лишь карточки 27 заданий (название, уровень, время) для карты экзамена на главной.
  Правите название, уровень, время или описание задания в `content/ege.js` — поправьте и карточку в `index.html`.
  Расхождение поймает тест `tests/test_content.py`.
- Правки из редактора (`GET /api/content`) гость получает урезанными: без задач и без текстов разборов,
  только правки учебника Python и полей карточек заданий.
- Картинки из редактора (`/api/media/<id>`) открыты по прямой ссылке: адрес случайный, но кто его знает — увидит.
- После входа страница перезагружается и подтягивает материалы, после выхода — перезагружается и забывает их.

## Локально

```bash
python3 tools/dev_server.py                 # сайт + API на http://127.0.0.1:8000
python3 -m unittest discover -s tests -v    # тесты API
```

## Сервер

Первая установка (Ubuntu):

```bash
sudo bash deploy/install.sh ваш-домен.ru
```

Сертификат Reg.ru: положите `fullchain.crt` (сертификат + цепочка CA) и `private.key` в `/etc/ssl/stackly/`
**до** запуска `install.sh`. Без них будет выпущен бесплатный сертификат Let's Encrypt.

Почта для восстановления пароля: заполните `SMTP_*` в `/etc/stackly/stackly.env`, затем
`systemctl restart stackly-api`.

Если письмо не доходит, пароль задаётся на сервере: `sudo bash deploy/set-password.sh почта@пример.ру`.
Пароль спрашивается дважды и на экране не виден; после смены все сессии пользователя закрываются.
Локально: `python3 app/stackly_api.py set-password почта@пример.ру` (база — `STACKLY_DB`).

Обновление вручную: `sudo bash deploy/update.sh` из папки с новой версией. Скрипт делает копию базы,
обновляет сайт, API, сервисы и конфиг nginx (домен и сертификат берутся из текущей установки).

## Учителя и домашние задания

Роли: **ученик**, **учитель** (преподаватель), **администратор**. При регистрации человек сам выбирает,
преподаватель он или ученик; администратора назначают на сервере.

- Учитель создаёт группы в разделе «Учителю» (`#teach`). У каждой группы свой код: ученик вводит его
  в личном кабинете и попадает в группу.
- У каждой задачи банка свой сквозной номер (#1, #2, …). В банке и в редакторе ДЗ задачи ищутся
  по номеру или диапазону («17», «5-9», «3, 12, 30-33»), по номеру задания ЕГЭ, сложности и тексту условия.
- Домашнее задание выдаётся группе или выбранным ученикам: задачи банка, темы Python, разборы
  заданий методички, срок сдачи и комментарий.
- Задачи 19–21 одной игры — комплект: отметили одну, и в задание сами добавятся все три (по порядку 19, 20, 21);
  убрали одну — уходит весь комплект.
- Ученик видит задания в разделе «ДЗ» (`#hw`): «Предстоит» и «Выполненные». Каждое задание открывается
  одной страницей (`#hw-<id>`): разборы, темы и задачи с проверкой ответа — без переходов между страницами.
- Учитель по каждому заданию видит статистику (`#teach-hwv-<id>`): кто сдал и когда, таблица
  «ученик × пункт» с числом попыток, сводка по каждой задаче.
- В группе — таблица учеников (решено, точность, серия, активность, сданные ДЗ) и карточка каждого ученика.
- **Материалы** (`#materials`). Преподаватель отмечает предметы, которые ведёт, и включает готовые модули
  (сейчас они есть по информатике: разборы ЕГЭ, учебник Python, шпаргалка, обзор экзамена). Ученики видят
  в «Материалах» и в своём кабинете только модули, включённые их учителями. Вкладки Python и разборов
  в подборе ДЗ тоже появляются, только если модули включены.
- **Тарифы преподавателей.** Бесплатный — до 5 групп, до 5 учеников во всех группах и до 2 ГБ (картинки, свои задачи
  с файлами, материалы, ДЗ). Про — без ограничений, плюс материалы платформы (разборы ЕГЭ, учебник Python, шпаргалка):
  ученик видит их, только пока у его преподавателя действует Про. Новому преподавателю — пробный Про на 14 дней,
  один раз (`TRIAL_DAYS`, `FREE_LIMITS` в `app/stackly_api.py`). Лимиты проверяет сервер: создание группы, вступление
  ученика по коду, сохранение картинок, задач и материалов; уже созданное после окончания Про остаётся.
  Оплаты на сайте нет: тариф и срок ставит администратор в карточке преподавателя. Поля `users.plan` (free/trial/pro)
  и `users.plan_until` (у Про без даты — бессрочно). Учителя, которые были до тарифов, получили пробный Про с дня обновления.
- **Telegram-бот** (`app/stackly_bot.py`, сервис `stackly-bot`). Для преподавателя — на тарифе Про: уведомления
  «ученик выполнил задание» и «новый ученик в группе», сводка, когда прошёл срок ДЗ (кто сдал, кто нет), вечерняя
  сводка в 20:00 по Москве; команды `/hw`, `/groups`, `/student Имя`, `/settings`, `/stop`; кнопка «Напомнить
  не сдавшим» (не чаще раза в 6 часов на задание). Ученик подключает бота, чтобы получать эти напоминания,
  и по `/hw` видит, что осталось сделать. Подключение — в кабинете (блок «Telegram»): одноразовая ссылка
  `t.me/<бот>?start=<токен>` на 15 минут. API в Telegram не ходит — кладёт сообщения в очередь `tg_outbox`,
  отправляет их бот. Настройка на сервере: создайте бота у @BotFather, впишите `STACKLY_TG_TOKEN` и `STACKLY_TG_BOT`
  (имя без @) в `/etc/stackly/stackly.env`, затем `systemctl restart stackly-api stackly-bot`. Без токена бот
  не запускается, а блок в кабинете видит только администратор (с подсказкой). Тест — `tests/test_bot.py`
  (поддельный Bot API на локальном порту).
- **Оплата Про через ЮKassa.** Преподаватель нажимает «350 ₽ за месяц» или «3 700 ₽ за год» в карточке тарифа
  (`POST /api/pay/pro`), платит на странице ЮKassa и возвращается на `#pay-return`, где сайт сверяет платёж
  (`POST /api/pay/check`). Уведомление ЮKassa приходит на `POST /api/pay/webhook`. В обоих случаях сервер не верит
  присланному, а запрашивает платёж у ЮKassa и проверяет статус, сумму, валюту и пользователя. Оплаченный срок
  прибавляется к действующему Про или пробному периоду, один платёж засчитывается один раз (таблица `payments`).
  Автопродления нет; возвраты — вручную в кабинете ЮKassa, тариф после возврата администратор меняет в карточке.
  Настройка: `STACKLY_YK_SHOP` и `STACKLY_YK_KEY` в `/etc/stackly/stackly.env`, адрес уведомлений в кабинете ЮKassa.
  Цены — `PRO_PRICES` в `app/stackly_api.py` и `PRO_PRICE` в `public/index.html` (оферта и главная). Тест — `tests/test_pay.py`.
- **Документы.** Публичная оферта — `#offer`, политика обработки персональных данных — `#privacy`, тарифы
  и порядок оплаты и получения доступа — `#pricing`, контакты и реквизиты — `#contacts`. Всё открывается без входа
  (этого требует ЮKassa при подключении платежей), ссылки — в подвале, тарифы — ещё и в шапке гостя.
  Реквизиты исполнителя — `EXECUTOR` в `public/index.html` (документы и страницы) и строка в подвале.
- **Карточка пользователя** (`#admin-u-<id>`, `GET /api/admin/user`). Администратор открывает её из «Пользователей»
  или «Обзора»: у преподавателя — тариф с формой смены (`POST /api/admin/plan`), занятые лимиты, группы, материалы;
  у ученика — прогресс, группы с преподавателями, выполненные ДЗ и ссылка на подробную статистику.
  В «Материалах» администратор видит материалы всех преподавателей, сгруппированные по авторам.
- **Свои материалы** (`#mat-new`, `#mat-<id>`, `#mat-edit-<id>`). Учитель собирает материал — текст в разметке сайта
  с формулами, таблицами, картинками и рисунками. Ученик видит материал, если учитель отметил «Показывать ученикам
  моих групп» или выдал его в ДЗ (вкладка «Материалы» в подборе). В ДЗ материал показывается целиком, пункт
  закрывается кнопкой «Отметить изученным». Удалённый материал скрывается, но не стирается. API: `GET/POST /api/materials`,
  `POST /api/materials/delete`; таблица `materials`, в ДЗ — `items.mat`, в прогрессе ученика — `mats`.
- **Рисунок.** В панели разметки любого редактора (задачи, методичка, материалы) есть кнопка «рисунок»: холст с карандашом,
  линией, стрелкой, прямоугольником, эллипсом, текстом и ластиком, шестью цветами, тремя толщинами, отменой и листом
  в клетку. Рисунок сохраняется картинкой PNG (`POST /api/media`) и встаёт в текст как `![](media:ID)`.
  Нажатие на картинку в превью открывает её на холсте — можно дорисовать, ссылка в тексте заменится на новую.
- Администратор видит обзор платформы (`#admin-home`): учителя с группами, учениками, заданиями, задачами
  и занятой памятью (картинки, свои задачи с файлами данных и выданные ДЗ), сводку по ученикам.
  Роли назначаются в «Пользователях» (`#admin`).

### Редактор (`#edit`)

- **Задачи.** Учитель создаёт свои задачи и правит только их. Задача относится либо к заданию ЕГЭ по информатике
  (1–27), либо к любому предмету: тогда указывают предмет и тему, а в банке и подборе ДЗ задачи фильтруются по предмету.
  Новые задачи получают постоянные номера с #1001.
- **Кто видит задачу.** Преподаватели и администратор видят общий банк платформы (встроенные задачи и задачи
  администратора). Свою задачу преподаватель по умолчанию видит один; её можно открыть всем преподавателям.
  **Ученик видит только задачи, выданные ему в ДЗ** — проверяет сервер: `GET /api/content/ege.js` отдаёт ученику
  банк только из этих задач (у каждой поле `n` — сквозной номер из полного банка), `GET /api/content` — только их правки.
  Выданная задача остаётся видна ученику, даже если автор потом её закроет.
- **Банк задач** (`#bank`) устроен по шагам: сетка номеров ЕГЭ и список предметов → список задач номера (`#bank-5`)
  или предмета (`#bank-s-<предмет>`) с фильтрами сложности и статуса → страница задачи (`#p-<id>`) с переходом
  к соседним. Комплект 19–21 — `#set-<id>`.
  Выдать в ДЗ чужую закрытую задачу нельзя: сервер это проверяет. Чужую или встроенную задачу можно скопировать
  и править копию. Администратор правит любые задачи, включая встроенные (#1–#462): правка хранится
  поверх встроенной, исходник можно вернуть, задачу можно скрыть из банка.
- **Методичка** (только администратор): разборы 27 заданий и 43 темы Python. Правки хранятся поверх
  встроенного текста, есть сброс к исходному.
- **Разметка** условий и текстов: `**жирный**`, `*курсив*`, `` `код` ``, `2^10^`, `log~2~`, списки
  (`- `, `1. `), таблицы (`| a | b |`), блоки `` ``` ``, картинки (загружаются кнопкой, хранятся в базе).
  Служебный символ как обычный — через `\`: `\^`, `\*`. Разметка всегда превращается в безопасный HTML.
- Картинки — PNG, JPEG, WebP, GIF до 1,5 МБ (большие уменьшаются в браузере перед загрузкой), SVG не принимаются.

### Посещаемость (`#admin-stats`)

Администратор видит посещаемость в разделе «Посещаемость» (кнопка есть и в личном кабинете):
сколько человек на сайте сейчас, посетители, визиты и просмотры за сегодня и за 7, 30, 90 дней или год,
график по дням (за год — по неделям), популярные страницы, источники переходов, телефоны и компьютеры, регистрации.

- Сайт при каждом переходе отправляет `POST /api/hit` с названием раздела (`bank-19`, `ege-5`, `hw`…) — без id задач,
  групп и ДЗ. Источник (`yandex.ru`, `vk.com`) отправляется только при открытии сайта.
- IP-адреса не хранятся и cookie для подсчёта не ставятся. Посетитель — хеш IP и браузера с солью дня,
  соль удаляется через два дня, поэтому одного человека можно узнать только в пределах суток.
- Боты и запросы без браузера не считаются. Записи старше 400 дней удаляются. Дни считаются по московскому времени.

Первого администратора назначают на сервере (пользователь должен быть зарегистрирован на сайте):

```bash
sudo bash deploy/set-role.sh почта@пример.ру admin
```

Прогресс и проверка ответов работают в браузере ученика, сервер хранит то, что прислал браузер.
Для домашних заданий этого достаточно, но технически подкованный ученик может отметить задачу
решённой, не решая её.

## Автодеплой

Каждое изменение в ветке `main` проходит тесты и само выкладывается на сервер
(`.github/workflows/deploy.yml`). Для этого в Settings → Secrets and variables → Actions нужны секреты:

| Секрет | Значение |
|---|---|
| `DEPLOY_HOST` | адрес сервера |
| `DEPLOY_USER` | пользователь SSH (`root` или пользователь с sudo без пароля) |
| `DEPLOY_SSH_KEY` | приватный ключ, открытый ключ которого добавлен в `~/.ssh/authorized_keys` на сервере |
| `DEPLOY_KNOWN_HOSTS` | вывод `ssh-keyscan -H <адрес сервера>` |

Пока секретов нет, деплой пропускается. Запустить вручную: Actions → Deploy → Run workflow.
